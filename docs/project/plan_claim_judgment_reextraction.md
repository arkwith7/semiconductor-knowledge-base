# PLAN — 거절결정 OCR 원문에서 청구항-단위 판단 재추출 (407 증대)

> **상태**: ✅ 실행 완료 (2026-07-22) — 아래 §7 결과
> **근거**: 사용자 지시(2026-07-22) — "407건을 늘릴 수 있다면 별도 작업으로 잡아야 한다"
> **관련**: [`prior_art_ontology_positioning.md`](prior_art_ontology_positioning.md) §3 C2 · TBox `PriorArtJudgment`

## 1. 문제 (왜 407인가)
청구항-단위 심사관 판단(어느 청구항이·어느 인용에·어느 근거로 거절됐나)은 현재 **160 특허·407 행**
뿐이다. 원인은 거절결정 **근거 원문이 라이선스로 제거**(`_excerpt_removed: True`)되어 청구항↔인용
매핑이 `ground_truth_evidence_v2`에 부분(407/656)만 남았기 때문 — 설계 한계가 아니라 데이터 가용성.

## 2. 실현 가능성 (실측 2026-07-22)
발췌 삭제 **전** OCR 원문이 `paper_data/data/processed/rejection_decisions/txt/`에 **430건** 실재.
- 현재 판단 보유 160 특허 · txt 보유 430 특허 · **재추출 후보 272**
- 그 중 **청구항+인용발명 구조 실제 보유 229** → 실효 대상
- 샘플 확인: `청구항 제1항 … 인용발명 1·2·3 … §29②` 구조가 원문에 존재
- **upside: 160 → ~389 특허(~2.4배), 판단 행 407 → 1,000+ 여지**

## 3. 방법 (설계)
1. **로컬 LLM 구조화 추출** (qwen3-coder, 라이선스 안전 — OCR 원문이 기기를 벗어나지 않음).
   입력: OCR txt. 출력(JSON): `[{target_claims:[...], cited_ref:"인용발명 N", legal_basis:"§29①/②"}]`.
   인용 참조(인용발명 N) → `cited_evidence_map`(이미 sdkb structured 보유)으로 실제 doc_id 해소.
2. **캐시로 결정화**(청구항 feature 분해기와 동일 패턴) — 재실행 시 무호출 재현.
3. **검증**: 기존 160 특허(ground truth)에 재추출을 적용해 target_claims 일치율 측정 → 정확도 확보 후
   나머지 229에 적용. 낮으면 규칙 병용.
4. **산출**: 보강된 판단 → `build_abox_claim_features` 의 evidence 입력을 교체/보강 →
   `PriorArtJudgment.aboutClaim` 대폭 증가.

## 4. 성공 기준
- 기존 160 대비 재추출 target_claims 일치율 ≥ 0.9 (검증셋).
- 청구항-단위 판단 특허 160 → ≥ 350.
- 지어내지 않음: OCR 구조 없는 43건·해소 실패 인용은 그대로 보고(§1 규약).

## 5. 비목표
- "겹치는 feature" 라벨링(여전히 도출·검증 대상).
- OCR 재수행(기존 txt 사용). §29 외 거절(선행기술 무관)은 대상 아님.

## 6. 파급
- 그래프 어휘 불변(기존 `PriorArtJudgment`·`aboutClaim` 재사용) — 인스턴스만 증가.
- 라이선스: OCR 원문은 로컬 처리만, 그래프엔 청구항 번호·근거·인용 링크(집계·구조)만 — 원문 텍스트 미적재.

## 7. 실행 결과 (2026-07-22)

`scripts/reextract_claim_judgments.py` — **규칙 기반 결정적 파싱**으로 확정(LLM은 이 작업에
불안정: 빈 추출·과대추출, 검증셋 Jaccard 0.16). 거절결정서의 `거절이유가 해소되지 않은 부분`
표는 매우 규칙적이라 `(청구항식, 법조항)` 행을 결정적으로 파싱하고 §29①/②만 취한다. 인용
doc 은 구조화 JSON 의 `cited_evidence_map` 으로 해소.

**핵심 발견 — GT(evidence_v2)가 오히려 노이즈다.** 검증셋 Jaccard(vs GT) 0.32는 정확도가
아니라 GT 노이즈를 반영한다: (a) `전항`(전체 청구항 거절)을 GT가 일부만 기록, (b) GT가 독립항
1을 습관적으로 추가하거나 이전 의견제출통지서 청구항을 섞음. 명시 케이스(`제4항 내지 제6항`
→[4,5,6])는 GT와 정확 일치. 규칙 파싱은 **최종 거절결정 표를 충실히 따르는 authoritative
소스**다. 스팟체크로 확인.

**upside (실측):**
- 재추출 판단행 **545** · 커버 특허 **226** (§29② 539 · §29① 6)
- 신규 특허(처음 청구항판단 생김) **92**
- **청구항-단위 판단 특허 160 → 252 (~1.6배)**
- 표 파싱 실패 101/430(§29 행 없음 — §42 등 선행기술 무관 거절이거나 형식 상이)

**통합:** `build_abox_claim_features.py` 의 판단 빌드를 evidence_v2 ∪ 재추출 union 으로 수정
(키 = target특허×cited_doc×ground, 청구항 집합 병합). 재빌드로 `PriorArtJudgment.aboutClaim`
증가 반영. 어휘 불변(기존 클래스·프로퍼티 재사용).

**한계:** aboutClaim 은 청구항 노드가 존재하는(=분해된) 청구항만 연결 — 종속항 다수는 독립항만
분해했으므로 미연결. 종속항 feature 분해는 후속 확장 여지. 라이선스: OCR 원문 로컬 처리만,
그래프엔 청구항 번호·근거·인용 링크(구조)만 적재(원문 미적재).
