# 01.code_spec/plans — 상류 계획 층

이 디렉터리는 **SDKB 자원 자체를 바꾸는 계획**을 둔다. 하류 실험 저장소
(`sdkb-prior-art-paper`)가 관찰한 결함과 요구가 그쪽 대장(`upstream/DEFECT-LEDGER.md` ·
`upstream/CR-*.md`)에 등재되면, **그 요구를 이 저장소가 어떻게 설계·구현할 것인가**는
여기에 선다.

## 왜 만들었는가 (2026-08-29 · 사용자 지시)

지금까지 T-Box·R-Box 보강 설계는 **하류 저장소의 계획 문서 안에** 있었다. 하류의 논조가
확정되면서 그 문서들이 하류 논문의 주장 체계와 어긋나기 시작했고, 더 중요하게는
**자원을 바꾸는 설계가 자원을 소유하지 않은 저장소에 있었다.** 하류 규약 §0.1 은
*"SDKB 결함은 상류에서 고친다 — 우회 패치는 스냅샷 출처를 거짓으로 만든다"* 이고,
같은 이유로 **그 수정의 설계도 상류에 있어야 한다.**

## 이름공간 — 하류의 `PLAN-0xx` 와 다르다

이 디렉터리의 번호는 **상류 전용**이며 하류 `sdkb-prior-art-paper/01.code_spec/plans` 의
`PLAN-071`·`PLAN-074` 등과 **같은 이름공간이 아니다.** 혼동을 막기 위해 각 계획은 머리말에
**출처**(하류의 어느 문서에서 왔는가)를 밝힌다. 번호는 재사용하지 않는다.

**출처가 하류가 아닌 계획도 있다 (2026-09-05 신설).** [PLAN-005](PLAN-005-prior-art-tool-qualification.md)
는 사용자가 이 저장소에 직접 낸 요구에서 출발했고, **하류의 하네스·규약·사전등록·판정에
종속되지 않는다.** 목표가 논문의 자원이 아니라 **도메인에서 실제로 쓰이는 도구**이기 때문이다.
하류가 얼린 스냅샷을 가져가는 것은 하류의 결정이며 그 계획의 임계경로가 아니다.

## 지위 — 이 디렉터리에 있다는 것이 승인이 아니다

계획 문서는 [CLAUDE.md §2](../../CLAUDE.md) 5단계의 **1단계(요구 정의)** 이며, **§2 의
정지 게이트를 그대로 탄다.** 파일이 저장소에 있다는 사실을 승인으로 읽지 않는다.
특히 T-Box·shape·IRI 규칙을 바꾸는 항목은 §2 3단계에서 **별도로 승인받는다** —
하류가 깨지기 때문이다(§0 하류 소비자).

## 이식성이 목표에 들어왔다 (2026-09-05 · 사용자 승인 · 안 C′-full)

**하류 논문이 반복해 받는 질문 둘에 답할 근거가 이 계획층에 없었다** — *"반도체 전용 아닌가
(바이오로 가면?)"* 와 *"한국 특허청 전용 아닌가(US·EP 로 가면?)"*. 이식성은 다섯 계획 어디에도
**목표로도 비목표로도 적혀 있지 않았다.**

사용자가 세 가지를 승인했다.

1. **안 C′-full** — 기존 IRI 는 불변인 채(안 A 의 계약), 신설 `pa:` 이름공간에 **도메인 슬롯과
   관할 슬롯 두 축**을 판다. 안 B 가 겨눈 것은 *재정의*가 아니라 **경계**였고, C′ 는 그 경계를
   IRI 파괴 없이 얻는다.
2. **PLAN-001 §1.2(b) 개정** — KR 문서종을 T-Box 클래스로 굳히고 `owl:disjointWith` 를 거는
   설계를 **§1.10(c) 가 대체한다**. 문서종은 `pa:documentRole` 을 갖는 개체가 되고, 배타성은
   관할 바인딩 모듈에서 말한다.
3. **`pa:underJurisdiction` 을 `MinedAxiom` 의 필수 provenance 로** — KR 결합용이성과 US §103
   KSR/TSM 은 같은 판단이 아니므로, 관할 표기 없는 공리 혼합은 §1-3 이 막는 종류의 오염이다.

**설계 정본은 [PLAN-001 §1.10](PLAN-001-prior-art-axiom-resource-redesign.md), 검증은
[PLAN-005 §3.5·§5 V6·§6 단계 8·9](PLAN-005-prior-art-tool-qualification.md), 종료 조건은
[PLAN-004 §3.2](PLAN-004-kb-sufficiency-roadmap.md) 가 진다.** 도메인 축은 **실증**(V6a)하고
관할 축은 **설계 보증**(V6b)까지이며 — 비용이 비대칭이기 때문이다 — **US 회수 성능은 재지
않는다**(PLAN-005 §7-8).

## 같은 날 함께 닫힌 결정 셋 (2026-09-05 · 사용자 승인)

1. **실행 순서의 정본은 [PLAN-005 §6](PLAN-005-prior-art-tool-qualification.md) 이다** — 단계
   1(V1–V4 기준선) · 2(통지서 인용 해소) · 3(`Prec` 산출)은 **병렬**. PLAN-004 §1 의 *"병렬
   가능한 것은 없다"* 는 **PLAN-001·002·003 사이에만** 적용된다(PLAN-004 §1 확정 블록).
2. **`Prec` 은 선택지 ①** — 2인 독립 코딩으로 산출하고 **완전 판정**을 낸다. 문턱
   `Prec ≥ 0.60` 은 승인 커밋 `15a9ae8` 값 그대로다(PLAN-004 §2 · PLAN-002 머리말).
3. **[CLAUDE.md §8](../../CLAUDE.md) 을 갱신했다** — 2026-07 부채 **네 건이 모두 해소**된 것을
   워킹트리 실측으로 확인하고, 부채 대장을 **§8(해소 기록) + §8.1(지금의 부채 — 자원 부적격)**
   으로 갈랐다. 있지도 않은 결함을 새 작업이 우회하는 것을 막기 위해서다.

## 지위가 바뀌었다 (2026-09-05 · 사용자 결정)

세 계획은 *"후속 논문(논문 B)의 착수 조건"* 으로 쓰였고, 하류 문서에는 *"현 투고본으로
넘어오는 것은 0건"* 이라고 적혀 있다. **그 전제가 뒤집혔다.** 하류 논지가 **"다양한 지식 기반
작업의 베이스가 될 필요충분조건을 갖춘 지식베이스의 사례와 그것을 만드는 방법"** 으로
피벗하면서(하류 `01.code_spec/plans/PLAN-092`), **T-Box·R-Box·A-Box 재구성은 하류 현 논문의
선행 조건이자 임계경로**가 되었다.

**세 문서의 본문은 한 글자도 고치지 않는다** — 머리말에 지위만 덧붙였다. 순서와 종료 조건은
[PLAN-004](PLAN-004-kb-sufficiency-roadmap.md) 가 진다. **여전히 §2 의 정지 게이트를 그대로 타며,
이 디렉터리에 있다는 사실은 승인이 아니다.**
