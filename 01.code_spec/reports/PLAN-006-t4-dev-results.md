## 5. 해석과 다음

1. **이번 반복의 결과로 말할 수 있는 것:** LLM 이 구조화 검색식을 짜고 집합 크기를 확인하며 조정하는 방식은 규칙 검색식보다 심사관 인용을 훨씬 많이 회수한다(dev 개발 결과).
2. **말할 수 없는 것** (평가된 것은 특정 자원과 `ontology_facets` 제공 방식이다 — 온톨로지 전체의 무용성으로 넓히지 않는다. 호출되지 않은 IPC 제안·용어 조회, 심사관 판단 사례 활용은 검증도 기각도 되지 않았다): 현재 형태의 온톨로지 도구(요소 패싯·검증 동의어·공통 번역·IPC 제안)가 LLM 에 **추가 효용**을 준다는 것 — dev 에서 d − b 는 0 과 구분되지 않는다. 규칙 검색식에서도 온톨로지 구성(c1–c3)은 키워드 기준선을 넘지 못했다.
3. 논문 중심 주장 "LLM 의 구조화 검색을 지원하는 온톨로지 도구의 추가 효용과 적용 조건" 에 대해 이 결과는 **추가 효용이 확인되지 않았다는 음성 결과**다. 적용 조건(어떤 질의·언어에서 도움이 되는가)은 이 데이터로 탐색할 수 있으나 탐색적 서술로만 남긴다.
4. 다음 반복을 연다면 새 가설로 1단계부터 — 이번 dev 결과를 보고 고친 방법을 이 dev 로 다시 검증하지 않는다. 일반화 확인은 A사 사례(외부 적용 가능성 · 한 기업으로 일반화 입증은 아님)와 라이브 KIPRIS 표본에서.

## 9. T4 v1 종료 결론 (2026-10-15 · 사용자 검토 반영)

> 기존 온톨로지 패싯 제공 방식의 추가 회수 이득은 제한적이었다(d − b: 질의별 +0.5%p · 쌍 기준 +1.1%p).
> 사후 표본 분석에서는 **부분 개시 문헌을 겨냥한 검색 계획의 부재**가 개선 가설로 도출되었다.
> 다음 평가는 **일반 검색 지침과 온톨로지 근거 계획의 효과를 분리해** 검증한다.

- "차이가 작다" 는 "동등하다" 가 아니다. 정식 동등성 판단에는 동등성 한계를 정한 검정과 **반복 생성에 따른 변동**(질의당 여러 실행) 측정이 필요하다.
  이번 bootstrap 은 **출원(질의) 단위**로 재표집했다 — 같은 출원에 묶인 인용 쌍을 독립으로 보지 않는다.
- 라이브 확인은 **검색 연산자와 실행 조건**을 확인한 것이며 실제 KIPRIS 회수 성능의 재현을 검증한 것이 아니다.
  라이브 결과 수(로컬의 중앙값 13.8 배)는 회수율이 높다는 뜻이 아니라 **검색 필드·형태소·IPC 조건 차이로 후보 범위가 달라진다**는 증거다.
  IPC 단일 코드는 **이번에 사용한 API(getAdvancedSearch)와 파라미터의 제약**으로 적는다.
