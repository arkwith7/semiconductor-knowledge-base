## 1. 무엇을 시험했는가 (한 문단)

아이디어(공개 청구항 1항·초록)를 입력해 KIPRIS 문법의 구조화 검색식을 만들고, 동결된 로컬 후보 코퍼스(41,031 · 정답 포함형)에서
실행해 **중복 제거 합집합 200건 이내**에 심사관 인용문헌을 얼마나 회수하는지 쟀다. 비교군은 규칙 기반 키워드 검색식(a′),
규칙 기반 온톨로지 검색식(c1–c3: 요소 패싯 · 검증 동의어 · 개념↔IPC · 심사관 판단 기반 우선순위), LLM 단독(b),
LLM + 온톨로지 도구(d)이다. b·d 는 같은 모델·프롬프트·검색 호출 상한을 쓰고 d 에만 온톨로지 도구가 있다.
모든 설정은 dev 개방 전에 동결했고(자원 해시·프롬프트 sha·지표 산식·bootstrap 시드), dev 197 질의에서 한 번 평가했다.

## 3. 쓸 수 있는 문장

1. "동결된 개발 평가에서 LLM 기반 구조화 검색식 생성은 규칙 기반 기준선보다 높은 회수율을 보였다(질의별 평균 회수율 약 2.8 배)."
2. "개념 패싯을 제공하는 온톨로지 도구(`ontology_facets`)를 LLM 에 추가했을 때의 개선은 확인되지 않았다(+0.5%p, 95% 구간 −3.2 ~ +4.2%p)."
3. "규칙 기반 검색식에 온톨로지 동의어·개념↔IPC·판단 기반 우선순위를 더해도 키워드 기준선 대비 개선은 확인되지 않았다."
4. "검색 구조(요소 부분 검색식의 합집합)와 공통 번역은 규칙 기반 검색식의 회수율을 크게 바꿨다(train 개발 측정: 0.072 → 0.187)."
5. 게이트 논지와 연결할 때: "자원을 추가하거나 에이전트가 도구를 호출하는 것이 그 자체로 업무 성능 개선으로 이어지지는 않은 사례" — **이 사례만으로 게이트 전체가 검증됐다고 쓰지 않는다.**

## 4. 쓰지 않는 문장

- "온톨로지는 효과가 없다" · "b 와 d 는 동등하다" — 구간이 작은 손해부터 작은 이득까지 포함하고, 동등성 검정이 아니다.
- "LLM 이 정답 문헌을 3배 더 찾았다" — 질의별 평균 회수율의 비이며, 총 회수 문헌 수의 배수가 아니다.
- IPC 제안·용어 조회·심사관 판단 사례 활용의 효과 — 호출되지 않았거나 시험되지 않았다(검증도 기각도 아님).
- "온톨로지가 근거 추적성을 제공한다" — 별도 평가(검색 항↔원문 요소 연결 정확도 등)가 없다.
- 실제 KIPRIS 전체 DB 에서의 발견 성능 — 정답 포함형 동결 코퍼스의 선별력 평가다.
- train 점검 구간의 d − b +0.045 를 성과로 인용 — dev 에서 재현되지 않았다.

## 5. 한계 (논문 한계 절에 그대로 옮길 것)

1. **dev 의 지위:** dev 는 어휘 채굴(harvest 범위 dev+train)·분석·사람 검증에 쓰인 적이 있어 개발 단계 평가다. 봉인 test 는 열지 않았다.
2. **코퍼스:** 출원인 기준 표집(삼성·SK하이닉스 · KSIA 소부장 188사) + 거절출원 + 서지가 확보된 인용문헌. 인용문헌 일부(dev 14 쌍)는 미수록.
3. **에뮬레이터:** KIPRIS 문법을 명세대로 재현한 로컬 실행이다(한글 부분일치 · 영어 단어 시작 접두 · 공백 AND 등은 가정). **라이브 KIPRIS 표본과의 일치 확인은 아직 하지 않았다.**
4. **LLM 실행:** 질의당 1회 · temperature 미지원 모델이라 산출물 동결로 재현한다. 신뢰구간은 질의 표본의 불확실성만 반영한다.
5. **언어:** 일본어 정답(dev 29 질의)은 모든 비교군에서 0–3.5% — 비목표 층이다.
6. **비용:** b·d 각 약 $12.8(dev 197 질의 · 추정 단가) — 청구서로 확정해야 한다.

## 6. 남은 상류 작업 (논문 이전에 끝내면 좋은 것)

- 라이브 KIPRIS 표본 일치 확인(§5-3) — 설계(§3.3)에 있었으나 미수행.
- 동결 로그 기반 누락 분석 — b·d 가 함께 놓친 문헌이 "검색됐으나 예산 때문에 채택되지 못함" 인지 "한 번도 검색되지 않음" 인지. 다음 온톨로지 가설은 여기서 확인되는 결손에서만 세운다.
