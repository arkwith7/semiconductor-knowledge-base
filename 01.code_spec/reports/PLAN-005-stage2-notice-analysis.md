> 근거 계획: [PLAN-005 §4 · §6 단계 2](../plans/PLAN-005-prior-art-tool-qualification.md).

## 0. 결론 먼저

**통지서는 세 층의 정보를 담고 있고, 셋의 난이도·확실성이 완전히 다르다.** 단계 2 를 하나의
작업으로 묶으면 가장 쉬운 것이 가장 어려운 것에 발목을 잡힌다.

| 층 | 실물 | 보유율 | 난이도 | 무엇이 되는가 |
|---|---|---:|---|---|
| **A. 법조항 × 청구항 표** | `순번 / 거절이유가 있는 부분 / 관련 법조항` | **99.4%** | 낮음 | 엣지·판단 단위 `legal_basis` |
| **B. 인용발명 정의줄** | `인용발명 1 : 공개특허공보 제10-2004-0108309호(2004.12.23)` | **72.2%** | 중간 | 인용문헌 해소 → `PriorArtJudgment` 승격 |
| **C. 구성 대비표** | `구성 / 청구항 N 발명 / 인용발명 M / 비고(동일·차이)` | **17.4%** | **높음** | **원소층 `coveredBy` · `uncoveredConcept`** |

**C 가 가장 값지고 가장 어렵다.** 심사관이 요소 하나하나를 대응시키고 `동일`/`차이`로
라벨링한 표이며, 이는 PLAN-005 §3.3 이 요구한 원소층의 **직접 증거**다. 그러나 OCR 로 열
정렬이 무너져 단순 규칙으로는 **보유 문서의 58%에서 한 행도 못 잡는다.**

## 2. 통지서 구조 — 전수 계수 (1,155건)

| 특징 | 건수 | 비율 |
|---|---:|---:|
| `[심사결과]` 블록 | 1,150 | 99.6% |
| **법조항 × 청구항 표** | **1,148** | **99.4%** |
| **인용발명 정의줄** (`인용발명 N :`) | **834** | **72.2%** |
| 구성 대비표 (`구성`…`비고` 동시) | 201 | 17.4% |
| §29①(신규성) | **259** | 22.4% |
| §29②(진보성) | 1,108 | 95.9% |
| §42(기재요건) | 494 | 42.8% |

**PLAN-005 §2.5 의 수치가 독립적으로 재현된다** — 그 절은 §29① 259 · §29② 1,108 · 문헌번호
75.2% 를 적었고, 이번 계수는 259 · 1,108 · 72.2% 다(문헌번호 정의는 정규식이 다르다).

### 2.1 신규성 승격의 **현실적 상한은 259 가 아니라 206 이다**

| 교차 | 건수 | 비율 |
|---|---:|---:|
| §29① 보유 | 259 | 22.4% |
| **§29① ∧ 인용발명 정의줄** | **206** | 17.8% |
| §29① ∧ 구성 대비표 | 24 | 2.1% |

**§29① 문서 53건에는 인용발명 정의줄이 없다.** 인용문헌을 해소할 원천이 문서 안에 없으므로
이 53건은 판단으로 승격될 수 없다 — 다른 경로(결정서·인용 코퍼스 역추적)를 쓰지 않는 한.

> **PLAN-005 §4 는 *"`RejectionReason` 277건을 인용문헌과 연결된 판단으로 승격"* 이라고
> 적었다. 그 277 은 `RejectionReason`(판단 근거) 단위이고 여기 206 은 **문서 단위**라 직접
> 비교되지 않는다. 그러나 상한이 존재한다는 사실은 같다 — **종료 조건을 277 로 못박으면
> 달성 불가능한 목표를 거는 것이다.** 3단계에서 근거 단위로 다시 세고 목표를 고쳐야 한다.

### 2.2 판단 어휘 분포 — 공리 유형의 원천

| 어휘 | 건수 | 비율 | PLAN-001 §1.2(c) 대응 |
|---|---:|---:|---|
| 차이점 / 상이한 점 | 718 | 62.2% | **`uncoveredConcept`**(잔여) |
| 단순 설계변경 | 434 | 37.6% | `substitutableWith` |
| 결합 곤란성·용이 | 229 | 19.8% | `combinableWith` |
| 동일하다 / 동일함 | 204 | 17.7% | `coveredBy` (동일) |
| 대응된다 / 대응됨 | 191 | 16.5% | `coveredBy` (대응) |
| 주지관용 | 58 | 5.0% | `isCommonKnowledge` |
| 치환 / 대체 | 57 | 4.9% | `substitutableWith` |

**`차이점`이 62.2%로 가장 흔하다.** PLAN-005 §3.4 가 신설하려는 `uncoveredConcept`(판정의
잔여 = 설명가능성의 본체)의 원천이 **긍정 어휘보다 많다.** 설계가 이것을 쓰지 않으면 가장 큰
원천을 버리는 셈이다.

## 3. 구성 대비표 — 원소층의 실물, 그리고 파싱 난제

### 3.1 무엇이 들어 있는가

```
구성 청구항 1 발명 인용발명 1 비고
반도체 기판 상에 형성된 제1 절연
1 기판상에 형성된 소자 분리막 동일
막
제1 절연막 내에 형성된 다수의 다
2 다수의 셀 다이오드 동일
이오드
```

**(본원 구성요소, 인용발명 개시, 심사관 판정) 삼중항이 표로 있다.** 이것이 PLAN-005 §3.3 의
원소층 `coveredBy` 가 필요로 하는 바로 그 자료이며, `차이` 라벨은 `uncoveredConcept` 의 근거다.
문단 단위 채굴(PLAN-002, `P_uniq` 3,044)보다 **정밀도가 근본적으로 높다** — 심사관이 직접
요소를 짝지어 놓았기 때문이다.

### 3.2 그러나 OCR 이 열 정렬을 무너뜨린다

행번호와 비고가 같은 줄에 오고 본원 구성 텍스트는 앞뒤 줄로 흩어진다. 단순 행 규칙
(`^\d+\s+…\s+(동일|차이)$`)의 성적은 이렇다.

| | 값 |
|---|---:|
| 구성 대비표 보유 문서 | 201 |
| 표 머리(`구성 청구항 N 발명 인용발명 M`) 인식 | 66 |
| **행 인식 총계** | **360행** (동일 194 · 차이 163 · 유사 3) |
| **한 행도 못 잡은 문서** | **116 / 201 (57.7%)** |
| 문서당 인식 행 수 | 중앙 0 · 최대 25 |

**즉 단순 규칙으로 회수 가능한 것은 문서의 42%·360행뿐이다.** 이 수를 늘리려면 열 재구성
휴리스틱이나 LLM 추출이 필요하고, 후자는 **§1-5 개인정보 제약에 걸린다** — 통지서에는
출원인·대리인·**심사관 실명**이 있으므로 `scripts/scrub_rejection_excerpts.py` 선행이 필수다.

## 4. 작업이 하나가 아니라 셋이다 — 3단계에서 갈라야 한다

| | 작업 | 원천 보유율 | 위험 | 산출 |
|---|---|---:|---|---|
| **A** | 엣지·판단 단위 `legal_basis` 부착 | 99.4% | 낮음 — 표가 정형이고 청구항 범위가 명시됨 | 하위집단 분석이 가능해진다(현재 2,534 엣지 전량 공란) |
| **B** | 인용 해소 → `PriorArtJudgment` 승격 | 72.2% (§29① 한정 시 206 문서) | 중간 — 문헌번호 표기 변형·코퍼스 미수록 | 신규성 축 9 → 최대 수백 |
| **C** | 구성 대비표 채굴 → 원소층 공리 | 17.4% · 단순 파싱 시 42% | **높음** — OCR 열 붕괴 · LLM 쓰면 스크럽 선행 | `coveredBy` · `uncoveredConcept` 의 **직접 증거** |

**A 는 B·C 와 독립이며 지금 바로 할 수 있다.** B 는 A 의 표를 쓰면 어느 거절이유 항목에
어느 인용발명이 걸리는지 좁힐 수 있어 **A 가 B 를 돕는다.** C 는 B 의 인용 해소가 있어야
인용발명 M 을 실제 문헌에 접지할 수 있으므로 **B 에 의존한다.**

> 순서는 **A → B → C** 이며, 셋을 한 작업으로 묶지 않는다. C 가 어려워서 A 가 지연되는 것이
> 이 저장소에서 반복된 실패 형태다.

## 5. 3단계(설계)에서 정해야 하는 것 — 지금 정하지 않는다

1. **A 의 접지 단위** — 표는 (청구항 범위 → 법조항)인데 엣지는 (거절특허 → 인용문헌)이다.
   **직접 대응이 아니다.** 청구항 범위를 매개로 붙일지, 판단(`PriorArtJudgment`) 단위로만
   붙일지.
2. **B 의 목표 수를 근거 단위로 재계수** — §2.1 대로 277 은 그대로 쓸 수 없다.
3. **C 의 추출 방식** — 규칙(열 재구성) / LLM / 하지 않음. LLM 이면 스크럽 선행과 모델·경로가
   3단계 승인 대상이다.
4. **결정서 `cited_evidence_map`(384건)과의 병합 규칙** — 같은 출원에 통지서와 결정서가 모두
   있을 때 어느 쪽이 우선이며, `citationStatus`(Provisional/Maintained/Withdrawn)를 어떻게
   파생할 것인가(PLAN-001 §1.2(b)).
5. **누출 규율** — 분할 축은 특허 패밀리다(PLAN-001 §1.6-1). 채굴은 dev 패밀리로 한정하고
   `check_leakage.py` 가 test 유래 0건을 검증해야 한다. **이 계수는 분할을 보지 않았다.**

## 6. 재현 명령

```bash
# §2 구조 계수
.venv/bin/python - <<'PY'
import glob, re
from collections import Counter
fs = sorted(glob.glob('data/sources/opinion_notices/txt/*.txt'))
pat = {"법조항×청구항_표": r'거절이유가\s*있는\s*부분\s*관련\s*법조항',
       "인용발명_정의줄": r'인용발명\s*\d+\s*[:：]',
       "구성대비표": r'구\s*성.{0,40}?비\s*고',
       "§29①": r'제\s*29\s*조\s*제\s*1\s*항', "§29②": r'제\s*29\s*조\s*제\s*2\s*항'}
c = Counter()
for f in fs:
    t = open(f, encoding='utf-8', errors='replace').read()
    for k, p in pat.items():
        if re.search(p, t, re.S): c[k] += 1
print(len(fs), dict(c))
PY

# §3.2 표 행 파싱 성적
.venv/bin/python - <<'PY'
import glob, re
from collections import Counter
row = re.compile(r'^\s*(\d{1,2})\s+(.*?)\s*(동일|차이|유사|대응)\s*$')
tot, zero, docs = Counter(), 0, 0
for f in sorted(glob.glob('data/sources/opinion_notices/txt/*.txt')):
    t = open(f, encoding='utf-8', errors='replace').read()
    if not re.search(r'구\s*성.{0,40}?비\s*고', t, re.S): continue
    docs += 1
    k = sum(1 for ln in t.split('\n') if row.match(ln))
    for ln in t.split('\n'):
        m = row.match(ln)
        if m: tot[m.group(3)] += 1
    zero += (k == 0)
print(docs, sum(tot.values()), dict(tot), "zero:", zero)
PY
```
