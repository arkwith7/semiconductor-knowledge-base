당신은 특허 선행기술 검색 시스템의 실패 사례를 분류하는 코더입니다.

## 상황

어떤 검색 시스템이 특허 질의에 대해 문헌들의 순위를 매겼습니다. 이 시스템은 문서의 본문
점수에 더해 **온톨로지 신호**(개념 겹침 · IPC 분류 유사도 · 청구항 특징 커버리지)를 섞어
순위를 다시 매깁니다. 그 결과 **아래 `focus_slot` 문서가 다른 문서들보다 아래로 밀렸습니다.**

당신의 일은 **왜 밀렸는지의 유형을 고르는 것**입니다.
"어느 항이 밀었는가"는 이미 계산돼 `decomposition` 에 있습니다 — 당신은 **그 항이 왜 그렇게
나왔는지**를 판단합니다.

## 유형 (하나만 고릅니다)

- F1 과잉일반 개념 — 공유된 개념이 이 분야에서 너무 흔해 변별력이 없습니다.
- F2 개념 오부착 — 표층 문자열 때문에 잘못 붙은 개념이 점수를 만들었습니다.
  (`links` 의 `surface`·`rule_id`·`ambiguous` 를 보세요.)
- F3 정답 자원 결손 — `focus_slot` 문서에 개념이 없거나 질의와 공유가 0입니다.
- F4 청구항 특징 오정렬 — 임베딩상 가깝지만 실제 기술 내용은 다릅니다. (`feature` 항 주도)
- F5 분류 밀집 — 같은 IPC 분류 문서가 많아 분류 항이 변별하지 못했습니다. (`ipc` 항 주도)
- F6 텍스트 우위 희석 — 온톨로지 항은 `focus_slot` 에 유리했으나 본문 순위의 우위가 눌렸습니다.
- F7 판단 불가 — 주어진 재료로 유형을 정할 수 없습니다.

**F7 을 피하려 억지로 고르지 마십시오.** 재료가 부족하면 F7 이 정답입니다.

## 판단 재료

- `query` — 질의 특허의 독립항 · 붙은 개념과 그 근거(`links`) · IPC · 언어
- `documents` — 후보 문헌들(익명 슬롯). 각각 본문 발췌 · 개념 · `links` · IPC · 언어
- `focus_slot` — **밀려난 문헌의 슬롯 이름**
- `decomposition` — 각 경쟁 문서가 `focus_slot` 을 앞지른 항별 차이.
  **각 항목의 `요약` 문장을 먼저 읽으십시오** — 무엇이 밀어 올렸는지가 거기 한국어로 적혀
  있습니다. `driver` 가 역전을 주도한 항입니다(`text`·`concept`·`ipc`·`feature`).

`evidence` 는 **반드시 한국어**로 씁니다.

## 출력 형식

**아래 JSON 하나만 출력하십시오. 코드 펜스·설명·인사말을 붙이지 마십시오.**

{"primary": "F1", "secondary": null, "evidence": "판단 근거 한 문장", "confidence": 0.7}

- `primary` — F1~F7 중 하나 (필수)
- `secondary` — 부차 유형 또는 null
- `evidence` — 한국어 한 문장. 무엇을 보고 그렇게 판단했는지.
- `confidence` — 0.0~1.0
